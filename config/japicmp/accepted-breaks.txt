# API breaks accepted by the API compatibility check (./gradlew japicmp, which ./gradlew build runs).
#
# The check compares each published artifact with its newest release on Maven Central that
# is no higher than the version in the root build.gradle, and fails on any binary- or source-incompatible change to a
# public or protected member. A break that is intended, for a major release, goes here with its reason. One file serves
# every artifact, because each element is fully qualified. japicmp can't see an interface becoming sealed. The packages in a project's apiCheck block are never
# compared, so they need no lines: the internal package io.github.brantunger.unruly.core, and, for unruly-engine, the
# packages that moved to unruly-engine-core. Each line is:
#
#   <major version> | <kind> | <element> | <justification>
#
# - major version: the major release the break ships in, such as 2. A line applies while the baseline is from an
#   earlier major version, so a 1.x hotfix released in the meantime doesn't turn it off. Once that major version is
#   released and becomes the baseline, the check warns that the line no longer applies, and it can be deleted.
# - kind: package, class, method or field. Every change to that element is accepted, not only the reported one.
# - element: as japicmp matches it. Parameter types are fully qualified and without generics, and a constructor
#   is named after its class:
#     io.github.brantunger.unruly.mvel
#     io.github.brantunger.unruly.api.RulesEngineBuilder
#     io.github.brantunger.unruly.api.RulesEngine#run(io.github.brantunger.unruly.api.FactStore)
#     io.github.brantunger.unruly.api.Rule#Rule(java.lang.String,java.lang.String,java.lang.String,java.lang.Integer,java.lang.String)
#     io.github.brantunger.unruly.mvel.MvelExpressionLanguage#LANGUAGE_NAME
# - justification: why users can live with the break. Required.
#
# A pull request that adds a line must be titled with a ! (for example feat!:), so it releases a new major version.
