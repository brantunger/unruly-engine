A rules engine for Java: rules are conditions and actions written in an expression language, such as MVEL, that an engine compiles once and runs against your facts from any number of threads.

Where to start

  1. {@link io.github.brantunger.unruly.api.RulesEngineBuilder} builds an engine: choose the match policy ({@code firstMatch}, {@code allMatches} or {@code uniqueMatch}), then its languages, imports, listeners and limits.
  2. {@link io.github.brantunger.unruly.api.Rule} is a condition, an action and a priority, created with {@link io.github.brantunger.unruly.api.Rule#builder()}.
  3. {@link io.github.brantunger.unruly.api.RulesEngine#load(java.util.List)} compiles a rule list; a broken rule fails there, not during a run. {@link io.github.brantunger.unruly.api.RulesEngine#run(io.github.brantunger.unruly.api.FactStore)} runs the rules against a {@link io.github.brantunger.unruly.api.FactStore}, such as a {@link io.github.brantunger.unruly.api.FactMap}.
  4. {@link io.github.brantunger.unruly.api.RuleListener} observes each run, condition and action; what {@code load} and {@code run} throw is in {@link io.github.brantunger.unruly.api.exception}.
  5. Writing an expression language starts at {@link io.github.brantunger.unruly.api.language}, and testing one at {@link io.github.brantunger.unruly.test}.

Modules

  • {@code io.github.brantunger.unruly.core}, the artifact {@code unruly-engine-core}: the API, the language SPI and the engine, without an expression language.
  • {@code io.github.brantunger.unruly}, the artifact {@code unruly-engine}: the MVEL language. It requires the core module.
  • {@code io.github.brantunger.unruly.test}, the artifact {@code unruly-engine-test}: tools for testing an expression language, for its own tests.
